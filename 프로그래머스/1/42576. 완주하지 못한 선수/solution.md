# 완주하지 못한 선수

## 1. 생각 방식

먼저 `completion`을 돌면서 완주한 선수 이름을 `HashMap`에 저장했다.

동명이인이 있을 수 있어서 이름마다 몇 명이 완주했는지 개수를 저장했다.

그다음 `participant`를 돌면서 해당 선수의 완주 개수를 확인했다.

```java
if(a == null || a == 0){
    return participant[i];
}
```

Map에 이름이 없거나 개수가 이미 0이면 그 선수가 완주하지 못한 선수이다.

완주한 기록이 있으면 한 명을 확인한 것이므로 개수를 1 감소시켰다.

```java
set.put(participant[i], a - 1);
```

## 2. 자료구조 선택 이유

선수의 **이름과 완주한 인원 수를 같이 저장해야 해서 `HashMap<String, Integer>`**를 사용했다.

동명이인이 있을 수 있기 때문에 `HashSet`처럼 이름의 존재 여부만 확인하는 것으로는 풀 수 없고, 이름별 개수를 저장해야 한다.

## 3. 시간복잡도

`completion`을 한 번 돌고 `participant`를 한 번 돈다.

`HashMap`의 `get()`, `put()`은 평균 `O(1)`이므로 전체 시간복잡도는 **O(N)**이다.

공간복잡도는 `HashMap`에 선수 이름을 저장하므로 **O(N)**이다.
