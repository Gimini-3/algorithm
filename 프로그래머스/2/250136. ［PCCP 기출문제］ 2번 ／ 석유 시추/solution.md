# 석유 시추

## 1. 생각 방식

먼저 전체 `land`를 돌면서 연결되어 있는 석유 덩어리들을 BFS로 찾았다.

석유 덩어리마다 `level` 번호를 하나씩 부여해서 `visited`에 저장했다.

```java
visited[nextX][nextY] = level;
```

그리고 각 석유 덩어리의 크기는

```java
groupSize[level]
```

에 따로 저장했다.

이렇게 하면 각 칸이 **몇 번 석유 덩어리에 속하는지**, 그 석유 덩어리가 **총 몇 칸인지** 바로 알 수 있다.

그다음 열을 하나씩 확인하면서 해당 열이 지나가는 석유 덩어리 번호를 `HashSet`에 넣었다.

같은 석유 덩어리를 한 열에서 여러 번 만날 수 있기 때문에 중복으로 더하지 않도록 했다.

마지막으로 해당 열에서 만난 석유 덩어리들의 크기를 전부 더하고, 그중 최댓값을 구했다.

## 2. 자료구조 선택 이유

연결된 석유 영역을 탐색해야 해서 `Deque`를 Queue처럼 사용해서 BFS를 돌렸다.

```java
Deque<Node> deque = new ArrayDeque<>();
```

`visited`에는 단순히 방문 여부만 저장하지 않고 **석유 덩어리 번호**를 저장했다.

```java
visited[x][y] = level;
```

`groupSize`에는 각 석유 덩어리의 전체 크기를 저장했다.

```java
groupSize[level]
```

각 열에서 같은 석유 덩어리가 여러 칸 존재할 수 있기 때문에 중복 계산을 막으려고 `HashSet`을 사용했다.

```java
Set<Integer> set = new HashSet<>();
```

## 3. 시간복잡도

처음 BFS 과정에서 모든 칸을 한 번씩 탐색하므로 `O(N × M)`이다.

그다음 모든 열을 다시 확인하는 과정도 `O(N × M)`이다.

따라서 전체 시간복잡도는 **O(N × M)**이다.

공간복잡도도 `visited`, `groupSize`, BFS Queue를 사용하므로 **O(N × M)**이다.
