# 두 큐 합 같게 만들기

## 1. 생각 방식

먼저 두 큐의 합 `sum1`, `sum2`를 구한다.

전체 합이 홀수라면 두 큐의 합을 똑같이 나눌 수 없으므로 바로 `-1`을 반환한다.

```java
if ((sum1 + sum2) % 2 == 1) {
    return -1;
}
```

두 큐의 합이 다르면 **합이 더 큰 큐의 맨 앞 값을 빼서 작은 큐의 뒤에 넣는다.**

```java
if (sum1 > sum2) {
    long x = dq1.pollFirst();
    dq2.addLast(x);

    sum1 -= x;
    sum2 += x;
}
```

### 왜 항상 합이 큰 큐에서 빼도 되는가?

모든 원소가 양수이기 때문이다.

목표 합을

```text
target = (sum1 + sum2) / 2
```

라고 하면 `sum1 > sum2`인 경우

```text
sum1 > target
sum2 < target
```

이다.

이때 작은 큐에서 값을 꺼내 큰 큐에 넣으면

```text
큰 큐 → 합이 더 커짐
작은 큐 → 합이 더 작아짐
```

이라서 목표에서 더 멀어진다.

반대로 큰 큐에서 값을 빼면 큰 큐의 합은 감소하고 작은 큐의 합은 증가한다.

두 큐를 이어서 하나의 배열이라고 보면 **슬라이딩 윈도우와 같은 구조**다.

```text
현재 합 > target → 앞쪽 제거
현재 합 < target → 뒤쪽 추가
```

원소가 모두 양수라서 합이 큰 상태에서 값을 더 추가할 필요가 없기 때문에 큰 쪽에서 빼는 방식으로 진행해도 된다.

---

### 반복 횟수 제한을 두는 이유

합을 같게 만들 수 없는 경우 계속

```java
dq1 → dq2
dq2 → dq1
```

로 원소가 이동하면서 반복될 수 있다.

두 큐의 원소를 이어서 보면 원소들의 **전체 순서는 바뀌지 않고 경계만 계속 앞으로 이동**한다.

```text
[ q1 영역 ][ q2 영역 ]
    ↑           ↑
  시작점       끝점
```

한 번 이동할 때마다 두 경계 중 하나가 한 칸씩 앞으로 이동한다.

전체 원소 개수를

```java
queue1.length + queue2.length
```

이라고 하면 각 경계가 전체 원소를 한 바퀴 이상 확인한 뒤에는 새로운 경우를 더 확인할 필요가 없다.

그래서 코드에서는 넉넉하게

```java
int limit = (queue1.length + queue2.length) * 2;
```

까지 확인하고, 그 안에 합을 같게 만들지 못하면 `-1`을 반환했다.

즉 `limit`은 **정확한 최소 횟수 공식이라기보다는 모든 의미 있는 이동을 확인한 뒤 반복을 끝내기 위한 안전한 상한선**이다.

## 2. 자료구조 선택 이유

한 큐의 **앞에서 값을 빼고 다른 큐의 뒤에 넣는 작업**을 반복해야 해서 `Deque`를 사용했다.

```java
pollFirst()
addLast()
```

합은 `int` 범위를 넘어갈 수 있기 때문에 `long`으로 계산했다.

## 3. 시간복잡도

두 큐의 경계를 한 방향으로만 이동시키면서 원소를 확인한다.

각 `pollFirst()`, `addLast()`는 `O(1)`이므로 전체 시간복잡도는 **O(N)**이다.
